## Security and cost decisions

All new assistant calls reserve quota in PostgreSQL before inference under a shared transaction advisory lock. A failed or interrupted request still consumes one reservation, preventing retry loops from spending more calls. Exact account/input/model/version cache hits use zero new calls. No raw prompt is stored in the reservation table; the response can contain consented private context and remains account-scoped. Cache records are removed after 30 days by housekeeping. Account deletion immediately erases cached response content, while prompt-free usage records expire under that retention policy.

Invoice status and all purchased effects now commit within one database transaction, including nested hosting/checkout savepoints. A failed effect rolls the payment transition back so a confirmed receipt can be reconciled again. Existing previously inconsistent paid invoices are not silently rewritten by this change; they require an explicit historical reconciliation audit.

New publication requires paid verification plus a clean scan associated with the same immutable commitment when malware policy is enabled. Missing/stale definitions, scanner errors, archive encryption/limits or detections fail closed. This does not delete the owner's private file or claim every file is benign. Bulk downloads still use the private storage gateway; the scanner consumes only already-budgeted verification materialization.
