## Rollback

On EC2, restore the old routing and restart the preserved services:

```bash
sudo cp /etc/caddy/Caddyfile.pre-sol-20261015 /etc/caddy/Caddyfile
pm2 restart validator api web
sudo systemctl reload caddy
pm2 stop validator-sol api-sol web-sol
pm2 save
```

Do not run the old setup script over the new release or reset either ledger. Future updates should build with validators paused or fully constrained, then restart the selected validator before checking the API; two busy test validators starved the frontend build on this instance.

## Incident 16–17 October: disk full

On 16 October at 09:19 UTC the 30 GB root volume reached 100%. The validator's own text log in the ledger directory had grown to 5.4 GB (6.2 GB in total), and the RocksDB ledger had no size cap. The validator then crash-looped about 14,000 times, the API exited on `ECONNREFUSED 127.0.0.1:11000`, and PM2 lost the `-sol` entries. An orphaned `next-server` kept serving the homepage, so the outage was only visible in API-backed pages. Traffic and uploads were not the cause: uploads go to S3, and the API saw about 1,260 requests in total.

Recovery on 17 October:

- Deleted the validator text logs and emptied the PM2 logs.
- The fastboot bank snapshot `snapshots/298303` had no account storage, so the validator panicked on load. It was moved with `accounts/` to `~/sol-ledger-broken-20261017`, and the validator restarted from `snapshot-298303-*.tar.zst`. Program and chain state were intact.
- `validator-sol` now runs with `--gossip-port 11050 --limit-ledger-size 200000 --log`, so logs go to PM2 instead of the ledger directory. RocksDB settles at roughly 4–5 GB.
- Process list saved with `pm2 save`.

Safeguards:

- `pm2-logrotate`: 50 MB maximum per file, 5 copies kept, compressed.
- `~/bin/disk-watchdog.sh` (source: `infrastructure/ec2/disk-watchdog.sh`) runs from cron every 5 minutes. Above 85% (`df`) it deletes text logs and caches, never chain data or the USDC ledger. It logs to `~/disk-watchdog.log` and to syslog with the tag `disk-watchdog`.
- The CloudWatch agent publishes `CWAgent/disk_used_percent` and `mem_used_percent`, which requires `CloudWatchAgentServerPolicy` on `edgebounty-ec2-role`. Alarm `edgebounty-disk-70` sends email through SNS `edgebounty-alerts`. CloudWatch reads about 9 points below `df`, so 70% in CloudWatch is about 79% in `df`.
- SSH allows `185.154.188.0/24` and `91.151.136.0/24`, because the operator's ISP rotates addresses.
